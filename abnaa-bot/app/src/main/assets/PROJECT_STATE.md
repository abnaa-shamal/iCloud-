# حالة المشروع الكاملة (للتسليم عند انتهاء الحصة المجانية)

آخر تحديث: السبت 2026-10-31، 02:00 (توقيت عمّان). اقرأ هذا الملف كاملاً قبل أي رد. اكمل من «أين وصلنا» بدون ما تسأل صاحب المشروع عن أشياء مكتوبة هون.

## 1) مين هو وكيف يشتغل

- الاسم: **Abo-tala** (دايماً بحروف إنجليزية حتى وسط الجملة العربية، **ولا تكتبه بحروف عربية أبداً**). الاسم الكامل بالإنجليزي: Khubaib Alramdan. يشتغل **من جواله فقط** (Infinix HOT 60 Pro+، أندرويد 16)، عنده ماوس وكيبورد للجوال.
- يبني بـ CodeAssist على الجوال ويستخدم GitHub من المتصفح. كل خطوة لازم تنفع من الجوال.
- بيتعب أحياناً: ردودك **قصيرة جداً**. أرقام وجداول ونعم/لا. لا شرح طويل.
- كل تقرير = **جدول** (البند | الحالة | تفصيل). الحالات: نجح / فشل / ما قدرت. وقل بوضوح اللي ما بتقدر عليه.
- **اسأل قبل أي فعل** وهو موجود. زعل لما أُعيد بناء بدون سؤال. كل بناء جديد يحتاج موافقته.
- أي أداة أو خدمة تقترحها لازم تكون **مجانية**.
- لما تعطيه ملف أو رابط: حط الرابط المباشر وخطوات الاستخدام بنفس الرسالة.
- روابط تنزيل التطبيقات: **رابط صفحة التحميل** (فيها تقدّم). روابط GitHub المباشرة بتعلّق عنده. تطبيق المشرف لا يوضع على صفحة التحميل.
- تصاميم: **لقطات حقيقية من الكود نفسه** (مش HTML ولا وصف). وبدو تصاميم مميزة مش شكل ذكاء اصطناعي عام.
- لما يكون غايب أو ما جاوب: كمّل شغل على `lab` وقدّم له تقرير لما يرجع.
- الأسرار: إذا ظهر أي سر له (كلمة سر، مفتاح، كود) بالمحادثة أو الملفات أو المستودع: خبّره فوراً وشيله.
- يسميني ويسميك «يا حبيبي»، لهجة أردنية دايماً.

## 2) المشروع

«أبناء الشمال» (Shajara One): حجز مقاعد لكباتن وركاب قرية الشجرة (خطوط إربد، عمّان، الزرقاء، وقريباً المفرق) بدل قروبات واتساب.

| الجزء | معرّف الحزمة | الاسم |
|---|---|---|
| تطبيق العميل | `jo.abnaashamal.rider` | A-B-N Ride |
| تطبيق الكابتن | `jo.abnaashamal.Cap` | A-B-N Cap |
| تطبيق المشرف | `jo.abnaashamal.admin` | المشرف |
| لوحة المشرف ويب | `admin-web` | (Vite + React) |

- المستودع: `abnaa-shamal/iCloud-` (عام). مجلدات: `app` (عميل + كابتن بنكهتين)، `admin-app`، `admin-web`، `rules-test`، `firestore.rules`، `docs` (صفحة التحميل).
- المستودع المرجعي القديم `Shajara-One`: **لا يعدَّل ولا يُرفع عليه شي بدون إذن صريح**. وهو منفصل عن مستودع البناء المدموج وعن مشروع Firebase.
- مشروع Firebase (Auth + Firestore): `shajara-rides-security-t-2632f`. أسرار البناء كلها بـ GitHub Secrets، لا شي منها بالمستودع.
- التقنية: Kotlin 2.4.10، Compose BOM 2026.09.00، Material3، Firebase BOM 35.0.2، osmdroid للخريطة المجانية، AGP **9.4.0** (على main و v2)، Gradle 9.6.0، JDK 21، compileSdk 37، targetSdk 36، minSdk 26. رقم النسخة = رقم تشغيل GitHub Actions (عميل/كابتن 1.5.N، مشرف 1.0.N).
- الـWorkflows: `build.yml` (يشتغل على push لـ main وv2 أو يدوياً)، `screenshots.yml`، `admin-shots.yml`. فيه 3 مهام: `build` (يبني الـ3 APK ويتحقق من التوقيع)، `rules-test`، `admin-web`.
- **مفتاح التوقيع: ما بنغيّره أبداً.**

## 3) الفروع (أربعة فقط، لا تضيف ولا تحذف)

| الفرع | الدور |
|---|---|
| `main` | النسخة المعتمدة. **ممنوع تلمسه أبداً بدون موافقته الصريحة وهو موجود** |
| `v2` | التطوير. كل دفعة عليه بتبني ملفات التطبيق |
| `lab` | التجارب. أي تجربة (تصميم، تحديث مكتبة، نغمة) عليه فقط. إذا ما عجبته نرجّعه لـ v2 بأمر واحد |
| `verify-gate` | صفحة التحميل. **لا تحذفه** |

v2 مدموج بـ main (الاثنين على نفس الكوميت `957bbec`). فروع الاختبار القديمة انحذفت.

## 4) آلية التحديث والإشعارات (مهم)

- العميل والكابتن: `Updater.kt` يقرأ `https://abnaa-shamal.github.io/iCloud-/apk/version.json` كل ~15 دقيقة بـ WorkManager، وإذا في نسخة أحدث بطلّع **إشعار واحد لكل نسخة** (قناة `app_update_v1`، نغمة `snd_system`) برابط صفحة التحميل. أيضاً يفحص قبول الحجز المسبق للعميل.
- المشرف: `Updater.kt` يقرأ آخر **5** Releases من GitHub ويدوّر على وسم `build-N`.
- **أندرويد: نغمة القناة ما بتتغير بعد إنشائها.** لتغيير نغمة التحديث لازم **قناة بمعرّف جديد** (مثلاً `app_update_v2`).

## 7) نغمة التحديث (قيد التنفيذ)

- الملف: `mixkit-clear-announce-tones-2861.wav` (WAV، 44.1kHz ستيريو، حوالي 3.97 ثانية، 700KB). يعجبه إنها عالية وواضحة. **الملف عنده، مش بالمستودع.**
- بانتظار جوابه: **1** = بدون قص (4 ثواني)، **2** = قص لأول ثانيتين مع تلاشي بسيط (مُوصى به).
- الخطة: حط الصوت بـ `app/src/main/res/raw/` (اسم بأحرف صغيرة)، قناة جديدة `app_update_v2`، بناء واحد على `lab` (بعد موافقته)، يجرّبه على تلفون عميل ثاني، وبعدين يقرر الدمج.
- هدفه: النسخة تنزل للكباتن والموثوقين «نظيفة بدون أخطاء»، ومع **2–3 نسخ احتياط**: لا تحذف Releases القديمة، خلّي آخر 3 نسخ شغّالة دايماً.

## 8) المؤجّل

1. ترحيب المشرف «يا هلا Abo-tala» مع نغمة.
2. عرض انتهاء الرحلة للعميل.
3. خانة المفرق على بطاقات الرحلات.
4. اقتراحات الأيقونات.
5. **إعادة ترتيب بطاقات العميل والكابتن**: فكرة BlaBlaCar للعميل (خط وقت عمودي، سعر بارز، سائق وتقييم) وinDrive للكابتن (بطاقات عروض، سعر كبير، زر قبول). ياخذ الفكرة ويعملها بطابع «أبناء الشمال» (مش نسخ حرفي). بيجيب صور تصاميم يعجبه ونبني من الكود **ونصوّر لقطات حقيقية** على `lab` قبل أي بناء.

### خدمة توصيل الأكل (فكرة جديدة، لسا ما انبنت)

- قرار: **لا تطبيق ثالث**. كل شي داخل تطبيقي العميل والكابتن (والمشرف يسجّل المطاعم). كله على `lab`.
- شكل الصفحة الرئيسية للعميل (على طريقة Careem): بطاقات خدمات كبيرة: «🚗 حجز مقعد» (الموجودة) و«🍔 توصيل أكل» (جديدة). عند الكابتن: تبويب «توصيل» جنب الرحلات والحجز المسبق.
- سير الطلب كما وصفه: العميل يطلب ← المطعم يستقبل ← المطعم يطلب من التطبيق **أقرب كابتن حسب GPS** ← الكابتن يجيب الأكل ويوصله.
- الأجرة **حسب اتفاق الكابتن والمطعم** (مش ثابتة). هو بيزوّد مواقع المطاعم.
- سؤال مفتوح: المطعم لازم يكون عنده واجهة ليطلب كابتن (حساب بسيط أو صفحة ويب مجانية)، وما قرر. اسأله.
- المراحل: 1) طلب نصّ حر + قبول الكابتن، 2) قوائم طعام وسلة، 3) حساب/صفحة للمطعم.
- قبل البناء: لقطات **حقيقية** من الكود (مولّد اللقطات `screenshots.yml` بيعمل فرع جانبي `design-shots-<فرع>`، ولازم يحذفه بعد ما يشوف الصور). لا بناء بدون موافقته.

## 10) على Abo-tala (مش عليك)

- إنشاء مستودع خاص `abnaa-bot` على GitHub (https://github.com/new) وقول «تم»، وبعدها ينرفع مشروع البوت عليه.
- اختيار نغمة التحديث (1 أو 2) و**نعم/لا** لتشغيل الاختبارات على `lab`.
- تفعيل «Branch protection» على `main` (Settings ← Branches) كحماية إضافية.
- مفتاح الـAPI: يكتبه بشاشة الإعدادات بس. إذا انكتب بأي ملف أو محادثة: يحذفه من موقع المزوّد ويسوّي واحد جديد.

## 11) بوت أبناء الشمال (هاد التطبيق)

- اسم التطبيق: **«Abo-tala Assistant»** بنفس هوية أبناء الشمال (ألوان الغابة والذهبي، نفس الشعار). المشروع: `abnaa-bot` (تطبيق Compose): محادثة مع نموذج الذكاء الاصطناعي (Anthropic أو متوافق مع OpenAI، حسب إعداداته) + زر «افحص البناء» بيقرأ تشغيلات GitHub Actions بجدول.
- مصدر البوت موجود كمان على GitHub بفرع `lab` داخل مجلد `abnaa-bot/`، وبيتبني يدوياً من Workflow «Build bot (lab)». هاد المجلد منفصل تماماً عن التطبيقات الثلاثة، وما بيعمل أي Release (عشان ما يخرّب فحص تحديث المشرف).
- إعدادات بناء البوت مأخوذة من مشروع Reem اللي بيشتغل على CodeAssist (AGP 8.5.2، Kotlin 1.9.24، Compose BOM 2024.09.00، compileSdk 35، JVM 17). السبب: CodeAssist ما قرأ إعدادات AGP 9 وطلع خطأ «JVM target 11 / 1.8». **أي تعديل لإعدادات البناء لازم يحافظ على نفس هالأسلوب.**
- **قراءة فقط**: ما في أي أمر كتابة على GitHub بالكود. إذا صار بدك تكتب، فقط على `lab` وبعد إذنه الصريح.
- ما بيبني التطبيقات ولا بيشغّلها على جوال حقيقي، ولا بيسمع الأصوات. هاي لازم يجرّبها Abo-tala بنفسه.
- مفتاح صوت «فرح» (للتحويل لصوت) **مش لهالبوت**. هو لتطبيق ريم.
- فكرة جاهزة لإضافتها: فحص بالخلفية كل 15 دقيقة (WorkManager) بإشعار لما يفشل بناء. وافقها بالمبدأ وما انبنت.
- أول ما يكمل مع بوت: ابدأ بسؤاله جملة وحدة: «وين وصلنا؟ بنكمل مع (النغمة / البطاقات / الاختبارات)؟»
